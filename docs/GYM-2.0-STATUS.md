# Gym 2.0 — статус разработки и безопасная проверка

**Ветка:** `gym-2.0-development-2026-11-20`  
**Статус:** черновик, не сливать в `main` до проверки на копии.  
**Основной клиент:** `index.html`, версия `2.0-dev.1`.

## Что реализовано в ветке

- Независимые фазы «Подготовка и выполнение» и «Отдых», кнопка «Иду делать».
- Отдых запускается без создания фиктивной записи подхода.
- Поправки начала отдыха (−15, −30, −60 секунд или произвольная величина).
- Сохранение незавершённого подхода и таймера в `localStorage`.
- Завершение занятия фиксируется по фактическому нажатию, а не по последнему подходу.
- Простой экран массы тела без оценивающего «коридора» и большой карточки на главном экране.
- Первые рекомендации по прогрессии при сопоставимых рабочих подходах с учётом сложности.
- Предварительное сравнение результатов двух циклов по совпадающим упражнениям.
- Просмотр архивных программ, если сервер предоставляет архив.
- Пилотные SVG-схемы тяги верхнего блока и жима ногами, движение тяги — только по нажатию.
- Проверки `tests/smoke.cjs` и `tests/server-smoke.cjs`.

## Сервер: только кандидат, НЕ опубликован

`apps-script/Code.gs.candidate` — исходный пользовательский `Code.gs` с **точечными расширениями**, не реконструкция и не замена текущего опубликованного развертывания.

В этом файле значение `TOKEN` сознательно скрыто. Реальные секреты нельзя сохранять в GitHub.

Добавлено:
- серверный архив программ с ключом операции и восстановлением старой программы после частичной ошибки;
- новые необязательные поля времени в столбцах O/P листа «Тренировки»;
- объявление поддерживаемых функций при `pull`;
- выдача архивов клиенту.

Клиент **не позволит заменить программу**, пока работающий сервер не подтвердит наличие архивирования. Это предохранитель от потери старого плана.

## Что осталось перед выпуском

1. Подключить кандидат серверного кода **только к тестовой таблице** с отдельным развертыванием Apps Script. Секреты не коммитить и не отправлять в чат.
2. Запустить клиент из отдельного тестового профиля браузера / с отдельным origin, чтобы не затронуть существующий `localStorage`.
3. Проверить реальный `pull`, `set`, `delset`, `weight`, `session`, `exercise`, `program`, повторную отправку и ошибки.
4. Проверить связки и дроп-сеты после перехода между фазами.
5. Проверить визуализацию на экране iPhone и подтвердить читаемость схем.
6. Сверить старую и новую статистику и исправить обнаруженные расхождения.
7. После полной проверки — отдельно согласовать публикацию `main` и обновление рабочего Apps Script.

## Запуск автоматических тестов

В среде с установленным Node.js:

```bash
node tests/smoke.cjs
node tests/server-smoke.cjs
```

Эти тесты **не обращаются к Google**, но проверяют локальную логику и серверную модель на имитации таблиц. Они не заменяют проверку на iPhone и реальную тестовую синхронизацию.
