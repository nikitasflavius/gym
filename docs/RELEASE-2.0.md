## Последовательность

### 1. Проверка и развёртывание сервера — действие владельца

1. Рабочая таблица → «Расширения» → «Apps Script». **Не открывать тестовую таблицу**.
2. Сохранить копию старого `Code.gs` локально; убедиться, что исходный `TOKEN` сохранён только приватно.
3. Заменить текст рабочего `Code.gs` полным текстом `apps-script/Code.gs.candidate`.
4. Заменить строку-заглушку `const TOKEN = '___';` на **прежний рабочий пароль** из старого `Code.gs`. Не использовать тестовый пароль, не передавать токен в чат и не коммитить.
5. Сохранить проект. «Развернуть» → «Управление развертываниями» → выбрать **действующее** веб-приложение → редактировать (карандаш) → выбрать **новую версию** → «Развернуть». Цель: сохранить прежний URL `/exec`, выбранный режим исполнения и доступ. Не создавать новый продакшн URL без необходимости.
6. Существующий клиент v1.2 должен продолжать читать и писать через прежний URL.
7. Для проверки нового сервера в **приватной вкладке** можно открыть прежний URL `/exec?action=pull&token=<рабочий_пароль>`. Проверить `ok:true` и `features.programArchive:true`, `features.restStats:true`. **Никому не посылать URL с токеном, не публиковать скриншот адресной строки**.

После подтверждения, что рабочий сервер отвечает, переходить к клиенту.

### 2. Клиент — выпуск из PR

1. Проверьте зелёные GitHub Actions.
2. Merge PR № 1 в `main` (не закрывать PR без merge).
3. Проверьте сайт, при необходимости обновите страницу PWA и дождитесь установки нового service worker `gym-shell-v4-2-0`.
4. Вкладка «Ещё» показывает `Версия 2.0.0`, а состояние — «Всё сохранено в таблице».
5. Убедитесь, что история подходов, завершённые сессии, комплексы и цикл № 3 сохранились, а URL и пароль в настройках те же.
6. Начните тестовую короткую сессию в **рабочем приложении только по необходимости** и проверьте O/P листа «Тренировки» после завершения. Для практической проверки лучше использовать настоящую тренировку, без фальшивых подходов в рабочем журнале.
7. Протестируйте установленную PWA на iPhone: экран блокировки/сворачивание/восстановление, корректировку отдыха, синхронизацию.

### 3. Откат

- Если до merge обнаружена проблема, оставить `main` как есть. Серверная версия обратно совместима с v1.2 при обычных операциях подходов/веса/тренировок.
- Если проблема после merge, откатить клиент по PR/коммиту в GitHub, не удаляя ни локальное хранилище браузера, ни рабочие строки таблицы. Новый Apps Script лучше не откатывать без необходимости: он поддерживает старый формат и новые поля. Если откат серверной публикации необходим, в «Управление развертываниями» можно выбрать прежнюю версию после проверки данных.
- Никогда не удалять `localStorage`, установленное приложение или живую таблицу ради попытки обновления без предварительного резервного копирования.
